# GitHub 语音会议转写与 VoiceStudio 项目调研

> 关联：本调研是 2026-10 深度重构（Electron → Tauri 2 + Rust，多引擎可插拔）的决策依据，落地见 [`ARCHITECTURE.md`](./ARCHITECTURE.md)。
>
> 调研日期：2026-10-26  
> 范围：GitHub 上与语音会议转写、桌面录音转写、会议机器人、VoiceStudio 相关的开源项目。  
> 方法：GitHub Search API 检索 + 项目 README / release / 语言统计核对；只将项目自述或发布资产可验证的信息写入正文。效果数据优先采用项目自测基准，未在真实会议语料上统一复测。

## 1. 结论摘要

- **最完整的本地会议助手**：Meetily。覆盖 macOS / Windows 桌面安装、实时/本地转写、摘要、导入、多模型、GPU 加速，社区规模和发布成熟度最高。
- **最强通用语音工作台**：VoiceStudio。定位不是会议助手，而是本地语音创作/克隆/配音/转写工作台；Electron 桌面端跨平台，模型生态和硬件矩阵最丰富，但 AGPL-3.0 与模型许可证需要商业评估。
- **macOS 隐私优先轻量方案**：Ghost Pepper、MacParakeet、Minutes。共同点是 Apple Silicon / 本地模型，差异在于 MacParakeet 功能最重、基准最透明；Minutes 面向 Markdown + MCP 记忆库；Ghost Pepper 更轻，适合听写和简单会议记录。
- **会议平台自动接入**：Vexa。通过机器人加入 Google Meet、Teams、Zoom，提供实时 WebSocket/API 转写与 Agent 工作区；不是传统桌面录音应用，部署复杂度明显更高。
- **自建服务端转写网关**：Jigasi。Jitsi 会议生态的 SIP/转写网关，可接 Google Cloud、Vosk、Whisper 定制服务、Oracle 等，适合会议平台集成而非个人桌面工具。
- **离线转写/说话人分离基础库**：WhisperX。Python 库，不提供桌面产品；适合作为自研会议转写管线的核心组件。

## 4. 项目逐项分析

### 4.1 Meetily

- 地址：https://github.com/Zackriya-Solutions/meetily
- 官网：https://meetily.ai
- 定位：隐私优先的本地 AI 会议记录助手，Granola / Otter / Fireflies 的开源替代。
- 技术栈：Tauri 单体应用，Rust 后端，Next.js 前端；使用 Whisper / Parakeet。
- 能力：
  - 本地实时会议转写、录音导入、重新转写。
  - 本地或自定义 OpenAI 兼容端点生成摘要。
  - 本地保存录音、模型、转写结果。
  - macOS Metal/CoreML；Windows Vulkan；Linux 可按硬件源码构建；CUDA 需自定义构建。
- 桌面端：提供 macOS ARM DMG、Windows x64 EXE/MSI；Linux 有构建文档。
- 效果与限制：
  - README 未给统一 WER/RTF 基准；评价需用自己的中文/英文会议集复测。
  - Windows 标准包要求 AVX2 x64；CUDA 不在标准包自动启用。
  - Speaker diarization 在 README 中标为 PRO 规划，不应假设社区版已稳定。
- 适合：希望开箱即用、跨 macOS/Windows、数据本地化的个人/团队。

### 4.2 VoiceStudio

- 地址：https://github.com/debpalash/VoiceStudio
- 中文镜像/翻译项目：https://github.com/bayshier/voicestudio-zh
- 定位：完全本地的 ElevenLabs 替代，覆盖语音克隆、语音设计、视频配音、听写、转写、有声书，README 宣称 646 语言。
- 技术栈：Electron + TypeScript UI，Python 后端；开发/构建涉及 Bun、Rust/Cargo；默认 VoiceStudio/OmniVoice，支持多引擎管理。
- 桌面端：Electron 是唯一桌面和 Web UI；0.5.3 为最后 Tauri 版本。提供 macOS、Windows、Linux 包和 Docker 文档。
- 硬件：
  - NVIDIA CUDA；Apple Silicon Metal；AMD Windows ROCm 可选；部分 GGUF 引擎 Vulkan。
  - CPU 可用但慢，约 5GB 空闲磁盘用于小型 CPU PyTorch。
  - Windows on ARM 实验性；Intel Mac 只建议 UI 连接远程后端。
- 会议相关能力：偏“录音/媒体转写 + 语音生产工作台”，不是会议机器人或纪要系统。
- 效果与限制：README 链接 benchmark/performance 文档，效果强依赖所选引擎与模型；AGPL-3.0，且模型权重、音色和生成物授权彼此独立，商用需逐项审计。
- 适合：想搭建本地语音内容生产流水线，或调研 ASR/TTS/克隆统一工作台的团队。

### 4.3 Ghost Pepper

- 地址：https://github.com/matthartman/ghost-pepper
- 定位：macOS Apple Silicon 上的全本地听写与会议转写菜单栏应用。
- 技术栈：Swift/macOS 14+，WhisperKit、FluidAudio、MLX Audio、LLM.swift、Sparkle。
- 模型：
  - Whisper tiny.en / small.en / small multilingual。
  - Parakeet v3，25 语言，约 1.4GB。
  - Qwen3-ASR 0.6B int8，50+ 语言，约 900MB，需 macOS 15+。
  - Nemotron streaming 0.6B 8-bit。
  - 清理模型 Qwen 3.5 0.8B/2B/4B。
- 能力：按住 Control 讲话、释放后粘贴；会议录音并生成 transcript/notes/summary Markdown；模型本地缓存。
- 效果与限制：README 未提供统一 WER/RTF；更新时间明显放缓；平台限定 Apple Silicon。
- 适合：Mac 用户、轻量听写 + 本地会议记录，隐私要求高但不需要跨平台。

### 4.4 Vexa

- 地址：https://github.com/Vexa-ai/vexa
- 官网/文档：https://docs.vexa.ai
- 定位：自托管会议转写 API 与 Agent 平台，通过 bot 加入 Google Meet、Microsoft Teams、Zoom。
- 技术栈：Python/TypeScript/Java；gateway、meeting-api、agent-api、runtime、admin-api、Redis、Postgres、对象存储；Docker Compose / Kubernetes / Helm。
- 能力：
  - Bot 加入会议并输出实时 transcript。
  - Redis/ WebSocket/API 流式输出。
  - 录音进入自有对象存储。
  - Agent 可查询会议工作区，支持 MCP。
  - STT 是独立 GPU 单元，使用 faster-whisper / OpenAI-compatible 服务。
- 桌面端：没有传统桌面应用；Terminal 是 Web 工作台。
- 效果与限制：
  - 官方状态表称 Meet/Teams/Zoom bot 与实时转写生产可用。
  - Speaker attribution 在重串音时约 4–7% 行会留空，不强行猜测。
  - WebSocket transcript multiplex、静态加密等仍在规划。
- 适合：需要平台级会议采集、API/Agent 集成、自托管服务端，而非单机桌面用户。

### 4.5 Minutes

- 地址：https://github.com/silverstein/minutes
- 官网：https://useminutes.app
- 定位：本地优先的“会议记忆库”，把会议、电话、语音备忘和听写保存为用户可拥有的 Markdown。
- 技术栈：Rust + TypeScript；桌面、CLI、MCP server、SDK 多形态。
- 能力：
  - 菜单栏录音、听写、Recall、Documents、Coach。
  - CLI 约 60 个命令，MCP 约 34 个工具。
  - 输出 Markdown + YAML frontmatter，可被 Obsidian、grep、Agent 使用。
  - 转写与 speaker processing 本地运行；授权文本才会发送给云端 Agent/摘要器。
- 桌面端：macOS ARM、Windows x64、Linux x64 均有发布资产。
- 效果与限制：README 未给统一 WER/RTF；更适合 Agent/MCP 工作流而非会议平台机器人。
- 适合：把会议记录纳入个人知识库、Claude Code/Codex/Cursor 等 Agent 工作流的用户。

### 4.6 MacParakeet

- 地址：https://github.com/moona3k/macparakeet
- 定位：Apple Silicon Mac 的本地语音应用，覆盖听写、文件/URL/播客转写、会议录音、AI 功能。
- 技术栈：Swift 6 + SwiftUI；SQLite/GRDB；FluidAudio CoreML、WhisperKit；Sparkle；yt-dlp。
- 能力：
  - 系统级听写、热键、文件批量转写、YouTube/播客链接转写。
  - 会议同时录制系统音频与麦克风，可仅录一路；实时本地预览、笔记、事后导出。
  - TXT/Markdown/SRT/VTT/DAPT/DOCX/PDF/JSON 导出。
  - 可选 OpenAI/Anthropic/Gemini/Ollama/LM Studio/Codex 等 AI Provider。
- 基准：项目公开 ASR benchmark，在 Apple M4 Pro 48GB、macOS 15 上测试：
  - Cohere Transcribe q8：LibriSpeech macro WER 2.07%，test-clean 1.49%，test-other 2.65%；约 11x 实时，峰值 RSS 约 11.6GB。
  - Parakeet v2/v3/Unified：约 81–93x 实时，115–131MB RSS；macro WER 2.38%–3.22%。
  - Whisper large-v3 turbo：macro WER 3.00%，约 14x 实时，274MB RSS。
  - 多语言 FLEURS 切片中，中文 CER：Whisper large-v3 turbo 11.56%，Cohere 12.49%，Nemotron 19.47%；Parakeet v3 不适合 CJK/韩文。
- 限制：Apple Silicon M1+；Cohere 只有批处理，无实时预览/时间戳/说话人；许可证为 NOASSERTION，二开需审 LICENSE。
- 适合：Mac 用户、追求模型选择和公开基准、可接受平台锁定。

### 4.7 Jigasi

- 地址：https://github.com/jitsi/jigasi
- 定位：Jitsi Meet 的 SIP 网关和会议转写服务端组件。
- 技术栈：Java；XMPP 控制室、SIP 客户端、Jitsi Meet 服务端集成。
- STT 后端：Google Cloud Speech-to-Text、Vosk WebSocket、Jitsi 定制 Whisper 服务、Oracle Cloud AI Speech；翻译可接 LibreTranslate/Bing/Google。
- 能力：服务端采集参会人音频，生成转写/翻译；适合会议平台级部署。
- 桌面端：无。
- 限制：只适合 Jitsi/SIP 生态；质量和语言完全取决于外部 STT 服务；部署需要 XMPP/SIP/服务端运维能力。
- 适合：自建 Jitsi 会议平台或需要服务端字幕/转写网关的团队。

### 4.8 WhisperX

- 地址：https://github.com/m-bain/whisperX
- 论文：https://www.robots.ox.ac.uk/~vgg/publications/2023/Bain23/bain23.pdf
- 定位：长音频时间准确转写 Python 库，不提供桌面端。
- 技术栈：Python、faster-whisper/CTranslate2、wav2vec2 强制对齐、VAD、pyannote diarization。
- 能力：
  - Whisper 批量转写。
  - 词级时间戳对齐。
  - pyannote 说话人分离。
  - VAD 切分，论文称降低 WER 并支持批量推理。
- 限制：数字、货币等不在对齐字典中的词可能没有时间戳；重叠语音效果不佳；说话人分离不完美；语言需要对应 wav2vec2 对齐模型；GPU/显存会影响批量。
- 适合：作为自研会议转写流水线的核心离线 ASR/对齐/分离组件。

## 5. 效果与能力评估视角

### 5.1 不能只看 Stars

Stars 表示关注度，不等于会议场景准确率。建议准备内部测试集：

1. 中文普通话会议、中英混说、专有名词、部门缩写。
2. 系统内录远端说话人 vs 麦克风本端说话人。
3. 串音、快速交接、静音回声、压缩音频。
4. 指标至少包含 WER/CER、首字延迟、最终稿延迟、RTF、内存、长会稳定性、说话人归属错误率。

### 5.2 桌面录音型 vs 会议机器人型

- **桌面录音型**：Meetily、Ghost Pepper、Minutes、MacParakeet。优点是无需会议平台权限、部署简单；缺点是依赖本机音频采集权限、混合音频分离和会议平台策略。
- **会议机器人型**：Vexa、Jigasi。优点是获得平台内参会人音轨/事件，适合团队 API 化；缺点是 bot 入会权限、合规通知、服务器运维和成本。
- **基础库型**：WhisperX。可控性最强，但没有产品化录音、纪要、存储、UI。

### 5.3 中文会议建议

- 优先验证 Whisper large-v3 / faster-whisper 路线；MacParakeet 基准显示 Whisper large-v3 turbo 中文 CER 优于其内置 Parakeet v3。
- Parakeet v3 在该基准中不适合中文/日文/韩文，不应作为中文会议默认选择。
- 若使用 FunASR/Paraformer，可复用当前本地 `D:\AICoding\meeting\model\models\iic` 中的流式 Paraformer，但需与 Whisper/VoiceStudio 候选统一测试。
- 会议产品还需处理标点、VAD、说话人分离、术语词表和摘要质量。

### 5.4 工程落地优先级

1. **最快验证产品体验**：Meetily（Windows/macOS）或 Minutes（含 Agent/MCP）。
2. **Mac 深度优化与模型对比**：MacParakeet + 其公开基准方法论。
3. **语音创作/多模型工作台**：VoiceStudio，但注意 AGPL 与模型授权。
4. **服务端/API 化**：Vexa；Jitsi 场景选 Jigasi。
5. **自研管线**：WhisperX + FunASR/Paraformer + pyannote/说话人聚类 + 会议纪要 LLM。

## 6. 推荐结论

- **个人 Windows/macOS 会议助手**：优先试 Meetily；若重视 Markdown/MCP 记忆库，试 Minutes。
- **Mac 本地隐私方案**：MacParakeet 综合能力最强、基准最透明；Ghost Pepper 更轻。
- **团队会议平台采集/API**：Vexa 更通用；Jitsi 自建生态选 Jigasi。
- **本地语音工作台/VoiceStudio 调研**：VoiceStudio 体量最大、跨平台、模型丰富，但它不是会议助手，商用需重点审 AGPL 与模型授权。
- **底层能力自研**：WhisperX 作为离线对齐/分离基线，再叠加 FunASR/Paraformer 的中文流式能力。
