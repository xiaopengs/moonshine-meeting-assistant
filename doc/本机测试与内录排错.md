# 本机测试与内录排错指南

> 面向 Windows 真机验证 · 更新于 2026-11-05
> 目标：解决「打开内录失败」，并给你一套可自助定位的工具。

## 一、先拿文件

| 文件 | 用途 | 获取方式 |
|---|---|---|
| `audio-probe.exe` | **免安装音频诊断**，双击/命令行运行，逐个真实打开输入流 | 优先：本目录附带的构建产物；或 CI 产物 `moonshine-windows-x64`；或本机 `scripts\build-windows.bat` |
| `*_x64-setup.exe`（NSIS） | 完整桌面应用安装包 | GitHub Actions → Artifacts / Release |
| `moonshine-meeting-assistant.exe` | 裸 exe（云 ASR 即可用，无需 Python） | CI 产物与裸 exe 一起提供 |

**为什么先给 `audio-probe.exe`**：它不依赖 WebView2、不依赖 Python、不需要任何 Key，单文件即可运行。内录问题 90% 出在「设备层」，用它能在 10 秒内定位，不必先装整个应用。

> CI 配置：把仓库里的 `scripts/build-windows.yml` 复制到 `.github/workflows/build-windows.yml` 后提交，推送 `main` 或手动 `workflow_dispatch` 即自动构建。
> 打开仓库 **Actions → Build Windows → 最新一次运行 → Artifacts → moonshine-windows-x64** 下载。
> （当前 PAT 无 `workflow` 权限，因此 CI 配置以模板形式提供，未直接放进 `.github/workflows/`。）

## 二、三步测试法

### 第 1 步：跑诊断（不录音）

在 `audio-probe.exe` 所在目录打开 **Windows Terminal / PowerShell 7**：

```bat
audio-probe.exe
```

输出分三段：**设备清单**（⭐内录 / 🔶疑似内录 / 普通输入）、**逐设备打开测试**（OK 或 FAIL + 原始错误）、**结论**。

### 第 2 步：验证内录真的有声音

播放一段音乐/视频，然后：

```bat
audio-probe.exe --level
audio-probe.exe --level 3      :: 采集 3 秒
```

`--level` 会**同时打开全部可打开设备**（模拟「麦克风 + 系统内录」双路并发），输出每个设备的音频块数、峰值、均值：

| 现象 | 判断 |
|---|---|
| 峰值 > 0.001，「检测到声音」 | ✅ 该设备是有效内录源，在主界面选它 |
| 正在播放却仍「静音」 | ❌ 选错了设备，或该设备不是真正的回环源，换一个再测 |
| 块数 = 0 | 设备被挂起/独占，检查是否被其他软件占用 |

### 第 3 步：把结果交给开发（可选）

```bat
audio-probe.exe --json > diag.json
```

把 `diag.json` 贴回来即可，里面含宿主、全部设备、每个设备的所有配置尝试与原始系统错误。

## 三、读懂诊断结果

**命中的配置**示例：

```
[0] OK   立体声混音 (Realtek)
    命中: 2ch/48000Hz/Default/I16 → 内部混单/重采样为 16kHz 单声道 f32
```

含义：设备只支持 48kHz 双声道 I16，程序自动混单并线性重采样到引擎要求的 16kHz 单声道。**这正是以前会失败的地方**（旧版只尝试 f32 + 16kHz/1ch + Fixed 缓冲）。

**失败明细**示例（点开「查看尝试明细」或看 `--json`）：

```
1ch/16000Hz/Default/F32: AUDCLNT_E_UNSUPPORTED_FORMAT
1ch/16000Hz/Fixed(2560)/F32: ...
2ch/48000Hz/Default/F32: ...
2ch/48000Hz/Default/I16: ...
```

程序会自动尝试 **5 种采样格式 × 多组采样率/声道/缓冲**，任一成功即启用；全失败才会报错，并保留每一条的原始错误。

## 四、Windows 系统内录：已内置 WASAPI 回环

> **2026-11-05 重要变更**：此前版本只枚举 `cpal` 的**输入设备**，而 Windows 的系统声音
> 根本不是输入设备——它必须以**输出设备（render endpoint）**为对象、加
> `AUDCLNT_STREAMFLAGS_LOOPBACK` 才能采集。这就是「设备列表里永远没有内录」的根因。
>
> 现在 `crates/core/src/audio/loopback_win.rs` 直接调用 WASAPI 实现回环采集，
> 设备列表会把所有**输出设备**（扬声器 / 耳机）追加为 **`（系统声音）`** 采集源。

**你不需要再启用「立体声混音」**（Realtek 新版驱动大多已移除该选项）。

### 怎么确认可用

1. 运行 `audio-probe.exe`，设备清单里应出现形如
   `[ 2] [系统内录] 扬声器 (Realtek(R) Audio)（系统声音）  2ch / 48000Hz`
2. 逐设备测试中，该设备应显示 `OK` 并给出
   `WASAPI 回环 OK：2ch/48000Hz/32-bit float → 内部混单/重采样为 16kHz 单声道 f32`
3. 播放一段音乐，执行 `audio-probe.exe --level 3`，该设备峰值应 > 0.001

### 若某个「（系统声音）」设备 FAIL

| 原因 | 处理 |
|---|---|
| 该输出设备被其它程序以**独占模式**占用 | 关闭它，或在 Windows 声音设置里改用另一输出设备 |
| 该设备当前**无活动音频会话** | 先播放声音再测（loopback 无播放时不产生数据包是正常现象） |
| 蓝牙耳机处于**免提(HFP)** 模式 | 切到立体声(A2DP)，或换有线耳机 |
| 驱动不支持 loopback | 换一个输出设备；或装虚拟声卡（VB-Audio Cable，其 `CABLE Output` 会被识别为 ⭐内录） |

### 旧方案（仅在极老系统上仍有参考价值）

1. 右下角音量图标 → 右键「声音」→「录制」选项卡
2. 空白处右键 → 勾选「显示禁用的设备」
3. 找到「立体声混音 / Stereo Mix」→ 右键 → 启用
4. 回到应用点「↻ 刷新设备」

## 五、桌面应用内怎么操作

- **输入设备面板 → 「🔧 音频诊断」**：与 `audio-probe.exe` 同一后端，逐个设备显示可打开性、命中配置、可展开的错误明细。
- **「系统内录」下拉**：列出全部采集源，「（系统声音）」与 ⭐内录 排在最前，麦克风在后。
- **日志面板**：启动录制后会打印 `麦克风已打开: xxx · 命中配置` 与 `系统内录已打开: xxx · 命中配置`，可核对有没有打开错设备。
- 若启动失败，错误会带上设备名与全部配置尝试次数，不再是笼统一句。

## 六、常见错误对照

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `未检测到任何音频输入设备` | 旧版前后端字段名不一致（`maxInputChannels` vs `channels`）导致列表被过滤空 | **已修复**，刷新页面即可 |
| `未检测到 Loopback，内录不可用` | 旧版仅靠名称关键词判定，漏掉 WASAPI 回环 / PulseAudio monitor | **已修复**，内录下拉放开全部设备 |
| `设备 [x] 无法打开输入流（共尝试 N 种配置）` | 设备只支持特定采样格式/采样率/缓冲 | 已自动多配置探测；若仍失败看明细里的原始 OS 错误 |
| `AUDCLNT_E_DEVICE_IN_USE` / 设备被独占 | 其他软件独占音频 | 关闭会议软件/播放器/录音机后重试 |
| 权限类错误 | 系统「麦克风隐私设置」未允许桌面应用 | 设置 → 隐私和安全性 → 麦克风 → 允许桌面应用 |
| 打开成功但转写无内容 | 选错内录源 | 用 `audio-probe.exe --level` 播放音乐验证电平 |
| 打开的是错误设备（蓝牙切换后） | 旧版按 index 定位，设备列表变化会错位 | **已改为按设备名优先定位**，index 仅兜底 |
